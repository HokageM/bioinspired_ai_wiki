# Neural grasp learning ? the self-learning cycle

> **End-to-end learning of sensorimotor skills for object grasping.**
>
> 1. **Gather samples linking object positions to motor actions by placing an
>    object at random positions**
> 2. **Train deep neural end-to-end network with invented samples for grasping**

Collected pairs: **(image, joint configuration)**.

## The cycle

> a) object in [[nico|NICO]]'s hand ? b) place at random position ?
> c) record the joint values and an image ? d) & e) **re-grasp the object with
> the memorised joint values**, and repeat the learning cycle

```
while True:
    obj_in_hand = True
    joints = random_reachable_configuration()
    move_to(joints); open_hand()             # (b) place the object
    image = camera.capture()                 # (c) record
    dataset.append((image, joints))          #     the label came for free
    move_to(joints); close_hand()            # (d) re-grasp, using the memory
    train(net, dataset)                      # (e) repeat
```

## Why this is clever

The robot **manufactures its own labels**. The joint configuration that placed
the object is, by construction, a configuration that picks it up again ? so the
correct answer is known **before** the image is taken, without a human, a
simulator or an annotation tool.

This is the module's first genuinely **self-supervised** system with a body.
[[hubert]] (L04) was self-supervised over audio; here the supervisory signal is
generated by *acting*, which is what [[embodiment-and-situatedness|situatedness]]
is supposed to buy you.

| System | Where the label comes from |
|---|---|
| [[backpropagation|Supervised nets]] (L03) | a human |
| [[word2vec]] / [[hubert]] (L04) | structure already in the data |
| **Neural grasp learning** (L08) | **the robot's own prior action** |

> [!warning] The training distribution is limited to what the robot can already do
> Every sample is a configuration NICO could reach *and* release from. The
> positions it most needs to learn ? awkward, occluded, near joint limits, where
> an analytic solution fails ? are exactly the ones this procedure cannot
> generate, because it cannot place an object there in the first place.
>
> The method therefore learns fastest where it is least needed. Not raised in
> the source. The same self-limitation afflicts any *act-to-label* scheme and is
> the price of removing the human.

## Data augmentation

> - **Randomised cutouts of distractor objects**
> - **Semantic information of target object** (e.g. red, round, tomato)

The first is [[data-augmentation]] exactly as L06 defined it, applied to close
the gap between clean single-object scenes and cluttered ones ? a **direct
countermeasure** to the distribution problem above, though the notes do not
present it that way.

The second is different in kind: it is not augmentation but **an extra input
channel**, attaching language to the visual target. That is the *semantics* leg
of NICO's *"fusing vision, motor and semantics"*, and it is the only point where
[[L04-embodied-language-processing]]'s programme ? words grounded in
sensorimotor interaction ? is actually built.

> [!note] Two augmentations doing two different jobs
> Cutouts change the **input distribution**; semantic labels change the
> **input space**. Filing both under "data augmentation" conflates them.
